# Product Problem

## The original tension

The admin system had several valid audiences:

- operational staff
- managers
- catalogue administrators
- payment-recovery staff
- business owners

Their questions were different.

Operational staff needed immediate queues. Management needed trends and performance. Catalogue administrators needed product-quality checks. Combining all of these into one large dashboard reduced clarity.

## Problems identified

- too many metrics had equal visual weight
- live operational counts and period analytics were mixed
- zero-value queues occupied attention
- payment failures lacked a persistent follow-up workflow
- WhatsApp tracking risked being interpreted as confirmed conversations
- catalogue quality checks could become expensive if calculated during page requests
- mobile layouts needed stronger hierarchy and spacing

## Product objective

Create an admin control centre that helps users answer:

1. What must I act on now?
2. Which queue is most urgent?
3. What happened during the selected period?
4. Where can I investigate further?
5. Which data is proven, and which is only an interest signal?
